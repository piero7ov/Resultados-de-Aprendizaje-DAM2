# Tipos de licencias de los ERP-CRM

Resumen de las explicaciones sobre licencias y comercialización de un ERP/CRM.

## Licencia propietaria comercial

El material presenta este modelo como una opción para vender un producto propio y mantener el control del código fuente. El cliente obtiene permiso para utilizar el software bajo unas condiciones; la entrega del código y los derechos de modificación o distribución dependen de lo acordado.

Se propone este enfoque para el ERP en desarrollo si el objetivo es comercializarlo conservando el control del producto.

## Software libre y soporte de pago

Como alternativa, se plantea publicar el software con una licencia libre, como GPL o AGPL, y obtener ingresos mediante soporte técnico, mantenimiento y otros servicios.

El material relaciona este modelo con la participación de una comunidad y la atención a los usuarios. La elección de licencia y el servicio de soporte son decisiones distintas.

## Licencias de las tecnologías utilizadas

Antes de elegir la licencia del producto, hay que revisar las licencias de sus dependencias y las condiciones de uso y distribución.

Los apuntes mencionan GPL, AGPL y LGPL, además de tecnologías como PHP, Apache, Linux y MongoDB. También señalan que las bibliotecas utilizadas con HTML, CSS o JavaScript pueden tener sus propias condiciones.

La explicación resume algunas restricciones con frases generales. No debe interpretarse que GPL o AGPL impidan cobrar por el software, ni que todas las tecnologías citadas tengan la misma licencia. La compatibilidad concreta debe comprobarse según la dependencia, su licencia y la forma de integrarla y distribuirla.

## Desarrollo a medida y producto propio

- **Desarrollo a medida (ad hoc):** se cobra por el trabajo y, en el ejemplo explicado, por entregar el código fuente al cliente. Los derechos que recibe deben quedar acordados.
- **Producto propio:** se mantiene el control del producto y se ofrece al cliente una aplicación o acceso a un servicio.

## Software como servicio (SaaS)

El cliente accede al software alojado en los servidores del proveedor.

El material destaca estas ventajas:

- Actualizaciones centralizadas.
- Corrección de errores sin que cada cliente instale parches.
- Gestión centralizada de versiones.
- Menor exposición a la copia de una aplicación instalada localmente.

## Contrato de licencia pendiente

Se plantea redactar más adelante un contrato de licencia o de uso para los clientes, con las condiciones del servicio.

El contrato queda pendiente hasta definir mejor las funciones y servicios del ERP. Primero se continuará desarrollando el producto y después se concretarán las condiciones de contratación.
